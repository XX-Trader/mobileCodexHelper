## 3. 产品定义

`mobileCodexHelper` 的目标不是把电脑远程桌面搬到手机上，而是提供一个足够安全、足够轻量的手机网页入口，让用户可以:

- 查看电脑上的 Codex 项目和会话
- 查看消息和执行状态
- 从手机继续发送消息，让电脑上的 Codex 接着工作
- 管理新设备审批和移动访问开关

## 4. 目标用户

当前仅面向单用户个人使用场景:

- 用户本人在 Windows 电脑上运行 Codex
- 用户希望在手机上继续查看和控制自己的会话
- 用户愿意通过 Tailscale 等私网方式访问，不追求公网裸露部署

不面向:

- 多人团队协作
- 多租户 SaaS
- 通用远程执行平台
- 高权限系统管理面板

## 5. 核心需求

### 5.1 移动查看与控制

- 手机端可以查看项目列表、会话列表和消息内容。
- 手机端可以继续发送消息，驱动电脑上的本地 Codex 会话继续执行。
- 手机端体验优先围绕“查看 + 聊天控制”，而不是开放全量高风险能力。

### 5.2 安全访问

- 系统默认只允许单一用户账号。
- 新设备第一次登录必须经过电脑端批准。
- 已批准设备需要进入白名单。
- 默认推荐使用 Tailscale 私网访问，而不是直接公网暴露。
- Node 应用和代理默认应保持本机回环访问模型。

### 5.3 Windows 桌面控制工具

- 提供桌面控制台查看:
  - 本地服务状态
  - 远程访问状态
  - 待审批设备
  - 已批准设备
  - 关键错误摘要
- 支持在桌面端批准或拒绝首次登录的新设备。
- 支持启动、停止和检查整套运行环境。

### 5.4 项目与会话收敛

- 移动端可见项目应支持白名单控制。
- 默认体验应聚焦 `codex`，不把上游全部 provider 能力无差别暴露出来。
- 项目需要尽可能保持“安全收敛”的交互边界。

### 5.5 语言与跨设备一致性

- 默认语言优先为简体中文。
- 电脑端和手机端应尽量共享同一套用户级语言偏好。
- 登录、待审批、错误提示等关键界面需要对移动端友好。

## 6. 非功能要求

### 6.1 可调试性

- 发生问题时应优先暴露真实错误，而不是静默失败。
- 应具备清晰的健康检查入口、日志目录、状态脚本和数据库状态检查点。
- 桌面控制工具应能给出足够直观的服务状态和错误摘要。

### 6.2 安全性

- 保留首次设备审批机制。
- 不应默认把高风险管理能力直接开放到移动端。
- 公开访问必须经过明确评估，不应成为默认路径。

### 6.3 可维护性

- 对上游 `claudecodeui` 的改动应通过覆盖层维护。
- 项目需要有明确的文档索引、长期记忆文件和任务台账。
- 需求、接口、技术文档与代码变更要同步。

### 6.4 部署可达性

- 普通用户应能通过便携版快速使用。
- 维护者应能通过源码版重建、调试和重新打包。
- Windows 是当前主要运行平台。

## 7. 成功标准

满足以下条件可视为当前产品目标达成:

- 本机可打开 `http://127.0.0.1:3001`
- 手机可通过私网地址访问
- 新设备首次登录时电脑端能看到待审批记录
- 电脑端批准后，手机可进入项目和会话列表
- 手机发送消息后，电脑上的 Codex 会继续执行
- 用户能通过桌面工具定位服务状态、白名单和远程访问状态

## 8. 当前已识别的增强需求

以下需求已经被明确记录，但不代表全部已完成实现:

- 会话处理中状态与未读状态更稳定
- 已读/未读跨设备同步
- 每个会话记住输入草稿和输入模式
- 图片/附件交互继续打磨，例如草稿保留、补充信息输入更顺手
- 多会话快速切换
- 夜间模式
- 浏览器通知
- 文件链接直达查看，尤其是 `.md`

这些内容的详细规划见 [docs/chat-experience-upgrade-plan.md](chat-experience-upgrade-plan.md)。

## 9. 范围边界

### 当前范围内

- 单用户移动控制面板
- Windows 本地桌面控制工具
- 私网访问与设备审批
- `claudecodeui v1.25.2` 覆盖式定制

### 当前范围外

- 多用户权限系统
- 公网裸露部署模板
- 通用远程桌面能力
- 复杂团队级后台管理
